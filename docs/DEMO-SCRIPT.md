# Neon Signal — Suggested Project Demonstration

Aim for a 3–5 minute recording. Use real devices or browser profiles and do not edit the recording to imply that an untested feature worked.

1. **Introduction (15–20 seconds):** State that Neon Signal is a browser-based multiplayer code-and-bluff game for 2–8 players, with a spectator view and five rounds.
2. **Create and join (30–45 seconds):** Show the host creating a room, share the room code, and show a second device joining. Briefly point out that spectators do not consume one of the eight player places.
3. **Explain the tutorial (20–30 seconds):** Open **How to Play** and show the six phases and five-round overview.
4. **Show a clue (30–45 seconds):** Lock a secret code and submit a structured clue. Explain that the game can verify the clue against the locked code.
5. **Show challenges (30–45 seconds):** Demonstrate one false clue being correctly challenged and, if practical, one true clue being challenged incorrectly. Show the score result.
6. **Show Round 3 (15–20 seconds):** Point out that Round 3 doubles both rewards and penalties.
7. **Show Watch a Game (20–30 seconds):** Join from a third device as a spectator. Show the scoreboard and live phase without taking a player slot.
8. **Finish at Round 5 (20–30 seconds):** Show `R5/5`, the “Last round” announcement, final reveal, and winner.
9. **Close (10 seconds):** Summarize the current architecture honestly: WebRTC peer-to-peer, Cloudflare TURN relay support, no traditional database in this release.

If you cannot record a full five-round session, demonstrate only what you have tested and clearly label any remaining item as planned work rather than completed functionality.
